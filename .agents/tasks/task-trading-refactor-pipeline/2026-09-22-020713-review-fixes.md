## Fixes

1. **SJ "Cocok" stat counted flagged rows as matched** (`sj-validation.js`).
   The `_renderResult` "Cocok" stat rendered `s.matched` behind a no-op ternary
   (`s.matched - s.mismatched < 0 ? 0 : s.matched`), so on the pre-invoice screen a
   matched-but-flagged row still counted as clean. Made the pure engine the single
   source of truth: `crossCheck` summary now exposes a `clean` count = rows that are
   `matched && !mismatch`. The UI shows `s.clean` (label sub changed to "Cocok & dalam
   toleransi"). `clean` is deliberately NOT `matched - mismatched`, because `mismatched`
   also includes unmatched-field rows, so that arithmetic double-subtracts.

2. **`crossCheck` matched/mismatched non-disjoint at the UI boundary** — resolved by the
   same `clean` field added in (1). Callers/UI no longer re-derive it. `summary` shape is
   additive (backward compatible): `total, matched, clean, mismatched, unmatchedRecap,
   unmatchedField`.

3. **Sales-funnel pickup fallback misattributed purchase DOs** (`funnel-report.js`).
   `salesFunnel` "Pengambilan Bertahap" used a negative `(!poId && !poNumber)` fallback,
   so a purchase-side DO stored without a `poId` (e.g. linked only via `sourceId`) was
   counted on the sales side. Replaced with an explicit positive sales marker only
   (`soId` / `soNumber` / `source === 'SO'`), and an early exclusion of any DO carrying a
   purchase link (`poId`/`poNumber`/`source==='PO'`/`sourceType==='PO'`+`sourceId`) or a
   cancelled DO. The negative fallback is dropped.

4. **Weighbridge netto zeroed on single-netto receipt** (`sales-purchase-extras.js`).
   The receive-modal save computed `net = gross > 0 ? gross - tare : 0`, so an operator
   entering only a netto (no bruto) persisted `netQty: 0`, and `invoiceBasisQty` then fell
   back to surat-jalan/ordered qty. The receive path now routes through
   `window._pipelineExtras.computeWeighing` (the pure engine that already honors a single
   netto), so the UI and engine cannot drift. The Netto cell is now an editable input: it
   is derived and read-only when a Bruto is entered, and directly editable when no Bruto
   is present. A safe inline fallback keeps behavior correct if the pipeline module is
   somehow absent.
